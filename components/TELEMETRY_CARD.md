# Telemetry Card Component

## Mission

The Telemetry Card component provides human-readable operational telemetry visibility across DOP-AI dashboards, maps, escalation systems, and public interfaces.

Built under the foundational doctrine:

> Dignity Over Power

The component prioritizes:

- rapid comprehension
- operational clarity
- telemetry visibility
- escalation awareness
- low cognitive load

---

# Core Principle

```text id="s1n5qx"
Telemetry should remain understandable at a glance.
```

---

# Component Purpose

Telemetry Cards act as:

- operational metric modules
- environmental visibility units
- infrastructure awareness components
- escalation support systems
- dashboard building blocks

The component should remain:

- compact
- readable
- calm
- operationally useful

# Primary Fields

## Metric Label

Purpose:
Identify telemetry category.

Examples:

- H₂S Levels
- Turbidity
- Flow Velocity
- Air Quality
- Pump Status

Visual priority:
High.

---

## Metric Value

Purpose:
Display primary operational telemetry.

Examples:

```text
42.7 ppb
385 cfs
ACTIVE
```

Visual priority:
Highest.

Typography should remain:
- large
- readable
- high contrast

---

## Escalation Status

Potential values:

- Green
- Yellow
- Orange
- Red

Purpose:
Provide rapid operational awareness.

---

## Trend Indicator

Purpose:
Show operational directionality.

Examples:

```text
↑ +12% past 3h
↓ -4% past 24h
Stable
```

Trend visibility improves:
- forecasting awareness
- anomaly recognition
- operational comprehension

---

## Sensor / Source Metadata

Purpose:
Provide telemetry traceability.

Examples:

```text
Sensor: TRV-H2S-001
Zone: South Basin
```

Metadata should remain:
- secondary
- readable
- non-dominant
